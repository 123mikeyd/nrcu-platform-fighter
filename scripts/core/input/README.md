# Core input API (P1)

Explicitly preload scripts from this folder; no global class registration required.

- `input_frame.gd`: typed tick/int, axis/Vector2 (positive Y down), held/pressed/released Dictionaries of semantic boolean buttons, source_id/String. `to_dict()` detaches nested data, encoding axis as `[x,y]`; static `from_dict(data)` restores it. Missing fields default neutral. Disk recording validation is stricter than this trusted in-memory conversion.
- `input_buffer.gd`: `advance(frame, hitstop=false)`, `peek(action)`, `consume(action)`, `clear()`, `debug_pending()`. FIFO requests contain action, sequence, original tick, press-time Vector2 axis and age. Default `window_ticks=6`: age 0 on enqueue, expires at age 6; one age increment per advancing non-hitstop sampled tick (not elapsed wall time). Duplicate source/action/tick presses cannot requeue; source ticks must be monotonic between clears. Unique sequence numbers remain monotonic across clear. Pressed semantic actions only; releases remain in InputFrame, not in the request queue. Match owner must preserve jump release through startup.
- `player_input_source.gd`: `sample(tick)` polls the physical keyboard or assigned pad exactly once per match tick. `device=-1` keyboard, nonnegative Godot pad device ID. `slot=0` defaults A/D/W/S, Space/F/G/E; slot 1 defaults arrows, Enter/K/L/O. Setting slot restores that slot's defaults, then apply/load custom bindings. `bindings` keys: left/right/up/down/jump/attack/special/shield; values are Godot physical keycodes. Opposing keys neutralize axes. `pad_bindings` maps semantic button names to Godot joy button IDs: jump=A, attack=X, special=B, shield=left shoulder. Optional down mapping is additive to stick-down. Left stick axes fixed. Axial `deadzone=0.2`: magnitude <= threshold becomes zero; remaining magnitude is preserved, clamped to [-1,1]. Down and optional tap jump activate beyond +/-0.5 normalized Y. `tap_jump=false` by default.
- `sample_snapshot(tick, keys={}, buttons={}, stick=Vector2.ZERO, present=true)` is a deterministic physical-state seam sharing the live normalization/edge code, for automated tests. Dictionary keys are keycodes/button IDs and values are booleans.
- `reset()` clears history and suppresses all buttons held at the next sample until their release. Movement axes remain responsive. Device/slot reassignment and hotplug signals also reset. Disconnected pad samples are neutral with empty button dictionaries and `connected=false`; reconnect suppresses held buttons. Match owner must **also clear its InputBuffer** on reset, pause, KO, reassignment and disconnect; source cannot own that separate queue. UI should observe `connected` for recovery messaging.
- `save_profile(path="user://core_input.cfg")` / `load_profile(path=...)` return Error. ConfigFile sections `player_<slot>` independently preserve keyboard/pad bindings, deadzone and tap jump. Device numeric IDs are deliberately not persisted (hotplug IDs are transient). Invalid profiles fail without changing settings; successful load resets edges. No InputMap or legacy configuration changes.
- `recorded_input_source.gd`: `record(frame)` appends detached dictionaries to `frames`; `rewind()` resets cursor; `sample(tick)` returns next detached recorded frame reticked to caller's tick, neutral at end. Original source_id retained for diagnostics. `save_recording(path)` / `load_recording(path)` return Error; JSON format `{version:1,frames:[...]}`. Invalid disk data is rejected atomically. Set `frames=[]` and rewind to start a fresh recording; do not append during playback unless intentional.
- `bot_input_source.gd`: `sample(tick, actor_position:Vector3, target_position:Vector3)` returns pursuit/attack/jump intents only; `reset()` clears edge history. Tunables `approach_distance=1.5`, `jump_height=1.0`. Minimal dummy, no recovery, attack cooldown planner, stage knowledge, or actor mutations.

Verification: root `tests/test_core_input*.gd`; red/green logs in `.verification/core/input/`. Synthetic sampling and hotplug signals are not physical-controller qualification. Two physical pads, browser focus/blur, and human feel are later integration gates.
